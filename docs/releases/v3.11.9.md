# v3.11.9 — 系统回收中断不再误判失败（中断语义区分 + 续跑入口）

## 背景

真机反馈（2026-10-11，3.11.6，一加 11/ColorOS 16）：Eta **后台执行 GUI 任务**时界面出现
「Runtime 运行失败 / 已停止」，任务中断且无法恢复。反馈报告（fork 提供）证据扎实：
**进程从未被杀**（同一 PID 连续存活 3h16m、crash 缓冲区为空），被销毁的是 **Service**；
`runtime_inflight_runs` 表**已保存完整 transcript/snapshot**，但 `onDestroy` 直接
`cancel("Agent Runtime 服务已停止")` 把 run 判为失败——**数据在，无续跑路径**。

代码验证确认：`persistCompletedRun` 只写 outbox 不清 checkpoint（数据确实保留）；
UI 恢复折叠（`recoverRuntimeRuns` → interrupted → 进度折叠）**已存在**，但**续跑路径不存在**，
且 cancel 语义把"系统中断"表述为"失败"。

## 修复

### 逻辑修复

1. **中断 ≠ 失败**（`AgentRuntimeService.onDestroy`）：
   `activeSession?.cancel(...)` 的 error 从「Agent Runtime 服务已停止」改为可识别标记
   `AgentRuntimeWire.SYSTEM_INTERRUPTED`——恢复层据此区分"系统回收中断"与"任务失败"。
2. **UI 恢复区分**（`AgentAppState` / `AgentPendingResultRecovery`）：
   error==SYSTEM_INTERRUPTED → 显示「任务被系统中断（进度已保留）」（`SystemNoticeCode.Interrupted`），
   而非「运行失败/已停止」。
3. **续跑路径**（`AgentAppState.resumeInterruptedRun`）：
   恢复折叠后，会话 history 已含中断前完整进度；「继续」以该 history 为基发起新 run，
   带防重复副作用引导（"已完成并验证过的步骤不要重复执行，尤其 GUI 动作与写操作"）。
   中断 run 在恢复时登记 `ResumableInterruptedRun`（有 transcript/快照才可续跑）。
4. **继续入口**（UI）：恢复后输入栏上方显示提示条「任务被系统中断，进度已保留。点击继续任务」，
   点击触发续跑（`AgentChatAction.ResumeInterruptedRun`）。

### 明确不做（治根另议）

- 内存基线优化（报告 §5.2）：降低中断**触发频率**的治根方向，但需真机测量定责
  （Dalvik 255MB 构成/EGL 74MB 是否可回收），为独立专项，真机实测后再做。
- 前台服务保活强改（报告 §5.3）：系统级/产品决策，另议。
- 自动无确认续跑：GUI 副作用风险，保持"提示确认后继续"。

## 验证

- 新增 1 个 @Test：`systemInterruptedRecoveryShowsInterruptedNoticeInsteadOfRuntimeFailed`
  （SYSTEM_INTERRUPTED → Interrupted 通知 + "进度已保留"）。
