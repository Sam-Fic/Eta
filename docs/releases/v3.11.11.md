# v3.11.11 — 上下文板块完善：容量守卫补 system/schema 预留 + 续跑知情缓冲

## 背景

承接 v3.11.10（编辑重发 CONTEXT_OVERFLOW 根治：boundary ID 定位 + 发送前容量守卫）后，
对上下文板块做系统性复查，确认两处遗留缺口：

1. **容量守卫漏拦**（G1）：v3.11.10 的 R2 守卫用 `rawEstimate`（未乘校准、中文 1 字≈1 token）
   估算编辑重发前缀历史，但**不含 system prompt 与工具 schema 的固定开销**。
   极端场景：historyPrefix 估 95%、加上 system/schema 实际超过 100%，守卫却未拦 → 仍可能被服务商以
   `CONTEXT_OVERFLOW` 拒绝（与修复前同类，只是概率更低）。
2. **续跑副作用缓冲不足**（G2）：v3.11.9 的续跑以折叠后完整 history 为上下文 + prompt 引导
   "不重复已执行步骤"；若模型忽略引导，可能重放 GUI/写操作。概率低但最恶劣后果需要一层用户知情。

## 修复

### 逻辑修复

1. **G1 容量守卫补系统/工具预留**（`AgentAppState.sendCurrentMessage` R2 分支）：
   守卫估算追加 `AgentHistoryTrimmer.TOOL_SCHEMA_RESERVE_TOKENS`（24K，复用既有常量而非自造数字）。
   仍用 raw 口径（保守），固定开销不构成"膨胀系数"，**不引入误拦**；
   解决"估 95% 实 102%"的漏拦盲区。

### prompt 约束（引导层，有效性需真机反馈验证）

2. **G2 续跑提示知情缓冲**（`AgentChatBody` 提示条文案）：
   「任务被系统中断，进度已保留。点击继续任务」追加「（若已涉及发送、修改或 GUI 操作，
   请先确认当前状态再继续）」——不改机制（仍需点击继续），仅给用户多一层知情，零行为回归。

## 验证

- 编译 + 受影响测试全绿：`AgentConversationRevisionReducerTest`。
- 全量回归：新增非环境失败 = 0。

  由守卫常数 + 全量回归兜底。
